C# Code

Adapters/InMemorySessionStore.cs
Driven Adapter
Default implementation of ISessionStore using ConcurrentDictionary for concurrent access without explicit locks. Registered automatically if the consumer does not register another implementation (ADR-002).
namespace BotFoundry.Telegram.Adapters;

internal sealed class InMemorySessionStore : ISessionStore
{
    private readonly Dictionary<long, UserSession> _store = new();
        public async Task<UserSession?> GetAsync(
        long chatId, CancellationToken ct = default)
    {
        _store.TryGetValue(chatId, out var session);
        return session
    }

    public async Task SaveAsync(
        UserSession session, CancellationToken ct = default)
    {
        _store[session.ChatId] = session
    }

    public async Task DeleteAsync(
        long chatId, CancellationToken ct = default)
    {
        _store.TryRemove(chatId, out _)
    }
}
Concept — internal + Driven Adapter (ADR-002)
internal ensures the consumer does not access this type directly — only through ISessionStore. O ConcurrentDictionary guarantees thread safety for multiple simultaneous messages of the same bot without manual lock management.
Adapters/TelegramMessageSender.cs
Driven Adapter — SDK
The only file in the library that uses Telegram.Bot. Implements IMessageSender delegating to ITelegramBotClient of the SDK. The rest of the library uses only the interface.
using Telegram.Bot;
using Telegram.Bot.Types.ReplyMarkups;

namespace BotFoundry.Telegram.Adapters;

internal sealed class TelegramMessageSender : IMessageSender
{
    private readonly ITelegramBotClient _client;

    public TelegramMessageSender(ITelegramBotClient client)
        => _client = client;

    public Task SendTextAsync(
        long chatId,
        string text,
        CancellationToken ct = default)
        => _client.SendMessage(chatId, text, cancellationToken: ct);

    public Task SendTextAsync(
        long chatId,
        string text,
        IReadOnlyList<string>? quickReplies,
        CancellationToken ct = default)
    {
        if (quickReplies is null or { Count: 0 })
            return SendTextAsync(chatId, text, ct);

        var markup = new ReplyKeyboardMarkup(
            quickReplies.Select(r => new KeyboardButton(r)))
        { ResizeKeyboard = true, OneTimeKeyboard = true };

        return _client.SendMessage(chatId, text,
            replyMarkup: markup, cancellationToken: ct);
    }
}
Concept — ADR-003 (SDK isolation)
The only using Telegram.Bot in the whole library is here. If the SDK has a breaking change, the fix stays contained in this single file — the Core and the consumer are not affected.
Adapters/TelegramPollingAdapter.cs
Driving Adapter
Hosted service that keeps the long polling loop with Telegram. Receives updates from the SDK, translates them into BotContext and triggers the Core pipeline. It is the only message entry point in the library.
using Telegram.Bot;
using Telegram.Bot.Polling;
using Telegram.Bot.Types;
using Telegram.Bot.Types.Enums;

namespace BotFoundry.Telegram.Adapters;

internal sealed class TelegramPollingAdapter : IHostedService
{
    private readonly ITelegramBotClient _client;
    private readonly IBotPipeline        _pipeline;
    private readonly IMessageSender      _sender;
    private readonly ISessionStore       _sessionStore;
    private readonly ILogger<TelegramPollingAdapter> _logger;

    // ... constructor via DI ...

    public Task StartAsync(CancellationToken ct)
    {
        var options = new ReceiverOptions
        {
            AllowedUpdates = [UpdateType.Message]
        };

        _client.StartReceiving(
            updateHandler:      HandleUpdateAsync,
            pollingErrorHandler:HandleErrorAsync,
            receiverOptions:    options,
            cancellationToken:  ct);

        return Task.CompletedTask;
    }

    public Task StopAsync(CancellationToken ct)
        => Task.CompletedTask;

    private async Task HandleUpdateAsync(
        ITelegramBotClient _,
        Update update,
        CancellationToken ct)
    {
        // Filter: text messages only
        if (update.Message?.Text is not { } text) return;

        var chatId  = update.Message.Chat.Id;
        var session = await _sessionStore.GetAsync(chatId, ct)
                      ?? new UserSession { ChatId = chatId,
                             ExpiresAt = DateTimeOffset.UtcNow.AddHours(24) };

        // Translation: Update (SDK) → BotContext (lib)
        var context = new BotContext
        {
            ChatId  = chatId,
            Text    = text,
            Session = session,
            Sender  = _sender
        };

        await _pipeline.ProcessAsync(context, ct);
    }

    private Task HandleErrorAsync(
        ITelegramBotClient _,
        Exception ex,
        CancellationToken ct)
    {
        _logger.LogError(ex, "Polling error");
        return Task.CompletedTask;
    }
}
Concept — Driving Adapter + Boundary Model
This adapter performs the translation Update (SDK) → BotContext (lib). After that, the object Update never appears again — the Core only sees BotContext. This is where the outside world "enters" the hexagon.
DependencyInjection/BotFoundryServiceCollectionExtensions.cs
Public Entry Point
The only public type of this project. Registers all the library's internal services in the .NET DI. The consumer only calls AddBotFoundry() in Program.cs — without knowing any internal type.
namespace BotFoundry.Telegram.DependencyInjection;

public static class BotFoundryServiceCollectionExtensions
{
    public static IServiceCollection AddBotFoundry(
        this IServiceCollection services,
        Action<BotFoundryOptions> configure)
    {
        var options = new BotFoundryOptions();
        configure(options);

        // SDK
        services.AddSingleton<ITelegramBotClient>(
            new TelegramBotClient(options.Token));

        // Infrastructure driven adapters
        services.AddSingleton<IMessageSender, TelegramMessageSender>();

        // ISessionStore: registers the fallback only if the consumer has not registered one before
        if (!services.Any(d => d.ServiceType == typeof(ISessionStore)))
            services.AddSingleton<ISessionStore, InMemorySessionStore>();

        // Core (pipeline — to be implemented in the next task)
        services.AddSingleton<IBotPipeline, BotPipeline>();

        // Driving adapter — keeps the polling loop
        services.AddHostedService<TelegramPollingAdapter>();

        return services;
    }
}

public sealed class BotFoundryOptions
{
    public required string Token { get; set; }
    public TimeSpan SessionExpiry { get; set; } = TimeSpan.FromHours(24);
}
Concept — DI Convention (ADR-002)
The check services.Any(d => d.ServiceType == typeof(ISessionStore)) is the fallback mechanism — the consumer registers their store before calling AddBotFoundry() and the library respects the choice.
Attention — future dependency
BotPipeline and IBotPipeline do not exist yet — they will be created in the next task (Core). For now, leave the registration commented out or use a placeholder so the build passes.

Rules of this Task

REGRA 01
All adapters are internal
Only BotFoundryServiceCollectionExtensions and BotFoundryOptions are public. The consumer never instantiates an adapter directly — only through DI.
REGRA 02
using Telegram.Bot only in two files
TelegramMessageSender.cs e TelegramPollingAdapter.cs are the only ones allowed to import the SDK. No other file in the project may reference types from Telegram.Bot.
REGRA 03
Registration of IBotPipeline stays commented out
BotPipeline does not exist yet. Leave the registration line commented out in DI so that dotnet build passes without errors. It will be uncommented in the Core task.
