BotForge.Telegram.Core

O núcleo do hexágono — orquestra mensagens, roteamento de comandos, execução de fluxos multi-step e fallback para LLM. Depende apenas de Abstractions; nunca referencia SDK ou infraestrutura.

Estrutura do Projeto

src/BotForge.Telegram.Core/zero dependência de SDK 
BotForge.Telegram.Core/
├── IBotPipeline.cs          ← driving port — contrato do pipeline
├── BotPipeline.cs           ← orquestrador principal
├── CommandRouter.cs         ← seleciona o ITopicHandler correto
└── StepRunner.cs            ← executa fluxos multi-step

Fluxo de Decisão do Pipeline

1
Auth (opcional)
Se IAuthMiddleware estiver registrado no DI, chama IsAllowedAsync. Se retornar false, pipeline encerra sem invocar handlers.
2
Step ativo? → StepRunner
Se session.HasActiveFlow, delega ao StepRunner. O runner executa ValidateAsync → ProcessAsync e atualiza a sessão com o próximo step ou limpa o fluxo.
3
Comando? → CommandRouter
Se a mensagem começa com /, o CommandRouter identifica o handler registrado pelo Command e invoca HandleAsync. Retorno FlowResult.Continue grava o fluxo na sessão.
4
Texto livre → ILlmBridge (opcional)
Se ILlmBridge estiver registrado, repassa a mensagem e envia a resposta ao usuário. Se não estiver registrado, ignora silenciosamente.
5
Salva sessão
Ao final de qualquer ramo, o pipeline chama ISessionStore.SaveAsync para persistir o estado atualizado da sessão.

IBotPipeline.cs
Driving Port
Contrato do pipeline — é a interface que o TelegramPollingAdapter usa para acionar o núcleo. Vive no Core porque é o contrato do hexágono do lado conduzido pelo adapter. 
namespace BotForge.Telegram.Core;

public interface IBotPipeline
{
    Task ProcessAsync(
        BotContext context,
        CancellationToken ct = default);
}
Conceito — Driving Port no Core
IBotPipeline fica no Core (não em Abstractions) porque é um contrato interno da lib — só o adapter de infraestrutura precisa dele. O consumidor nunca invoca o pipeline diretamente.
BotPipeline.cs
Orquestrador
Implementação central do pipeline. Recebe o BotContext, executa os 5 passos do fluxo de decisão e garante que a sessão seja sempre salva ao final — mesmo em caso de exceção não tratada. 
namespace BotForge.Telegram.Core;

internal sealed class BotPipeline : IBotPipeline
{
    private readonly ISessionStore               _sessionStore;
    private readonly CommandRouter                _router;
    private readonly StepRunner                   _stepRunner;
    private readonly IAuthMiddleware?              _auth;
    private readonly ILlmBridge?                  _llm;
    private readonly ILogger<BotPipeline>          _logger;

    // Injeção via DI — IAuthMiddleware e ILlmBridge são opcionais
    public BotPipeline(
        ISessionStore      sessionStore,
        CommandRouter      router,
        StepRunner         stepRunner,
        ILogger<BotPipeline> logger,
        IAuthMiddleware?   auth  = null,
        ILlmBridge?        llm   = null)
    {
        _sessionStore = sessionStore;
        _router       = router;
        _stepRunner   = stepRunner;
        _logger       = logger;
        _auth         = auth;
        _llm          = llm;
    }

    public async Task ProcessAsync(
        BotContext context, CancellationToken ct = default)
    {
        try
        {
            // 1. Auth
            if (_auth is not null)
            {
                var allowed = await _auth.IsAllowedAsync(context, ct);
                if (!allowed) return;
            }

            // 2. Step ativo
            if (context.Session.HasActiveFlow)
            {
                await _stepRunner.ResumeAsync(context, ct);
                return;
            }

            // 3. Comando
            if (context.Text.StartsWith('/'))
            {
                await _router.RouteAsync(context, ct);
                return;
            }

            // 4. Texto livre → LLM
            if (_llm is not null)
            {
                var reply = await _llm.ProcessAsync(context.Text, context, ct);
                await context.SendAsync(reply, ct);
            }
        }
        finally
        {
            // 5. Persiste sessão sempre
            await _sessionStore.SaveAsync(context.Session, ct);
        }
    }
}
Conceito — finally garante consistência
O bloco finally garante que a sessão sempre seja salva — mesmo que o handler lance uma exceção não tratada. Isso evita sessões presas em estado corrompido entre mensagens.
CommandRouter.cs
Router
Recebe a coleção de ITopicHandler registrados pelo consumidor e constrói um dicionário de lookup pelo Command. Em runtime, localiza o handler em O(1) e invoca HandleAsync. 
namespace BotForge.Telegram.Core;

internal sealed class CommandRouter
{
    private readonly IReadOnlyDictionary<string, ITopicHandler> _handlers;
    private readonly ILogger<CommandRouter>                  _logger;

    public CommandRouter(
        IEnumerable<ITopicHandler> handlers,
        ILogger<CommandRouter>     logger)
    {
        _logger   = logger;
        _handlers = handlers.ToDictionary(h => h.Command, StringComparer.OrdinalIgnoreCase);
    }

    public async Task RouteAsync(
        BotContext context, CancellationToken ct)
    {
        // Extrai o comando — ex: "/start args" → "start"
        var command = context.Text[1..].Split(' ')[0].ToLowerInvariant();

        if (!_handlers.TryGetValue(command, out var handler))
        {
            _logger.LogWarning("Comando não registrado: {Command}", command);
            return;
        }

        var result = await handler.HandleAsync(context, ct);

        // Se o handler iniciou um fluxo, grava o tópico ativo na sessão
        if (!result.IsComplete)
            context.Session.ActiveTopic = command;
    }
}
Conceito — Lookup O(1)
O dicionário é construído uma única vez no construtor (startup). Em runtime, cada mensagem faz apenas um TryGetValue — independente do número de handlers registrados.
StepRunner.cs
StepRunner
Executa um fluxo multi-step em andamento. Localiza o step ativo pelo ActiveStepId, valida a resposta do usuário e processa o resultado — avançando, redirecionando ou encerrando o fluxo. 
namespace BotForge.Telegram.Core;

internal sealed class StepRunner
{
    private readonly IReadOnlyDictionary<string, IConversationStep> _steps;
    private readonly ILogger<StepRunner>                          _logger;

    public StepRunner(
        IEnumerable<IConversationStep> steps,
        ILogger<StepRunner>             logger)
    {
        _logger = logger;
        _steps  = steps.ToDictionary(s => s.StepId, StringComparer.OrdinalIgnoreCase);
    }

    public async Task ResumeAsync(
        BotContext context, CancellationToken ct)
    {
        var stepId = context.Session.ActiveStepId;

        if (stepId is null || !_steps.TryGetValue(stepId, out var step))
        {
            _logger.LogWarning("Step não encontrado: {StepId}. Limpando fluxo.", stepId);
            context.Session.ClearFlow();
            return;
        }

        // Valida — se inválido, repete a pergunta
        var valid = await step.ValidateAsync(context, ct);
        if (!valid)
        {
            await step.AskAsync(context, ct);
            return;
        }

        var result = await step.ProcessAsync(context, ct);

        switch (result.Kind)
        {
            case StepResultKind.Complete:
                context.Session.ClearFlow();
                break;

            case StepResultKind.JumpTo:
                context.Session.ActiveStepId = result.TargetId;
                if (_steps.TryGetValue(result.TargetId!, out var next))
                    await next.AskAsync(context, ct);
                break;

            case StepResultKind.Continue:
            default:
                // ActiveStepId já deve ter sido atualizado pelo step em ProcessAsync
                break;
        }
    }
}
Conceito — Responsabilidade do step em Continue
Em StepResultKind.Continue, é responsabilidade do ProcessAsync do step atualizar context.Session.ActiveStepId para o próximo step. O runner não assume sequência implícita — bifurcações são controladas pelo consumidor.
Conceito — AskAsync em JumpTo
Quando o resultado é JumpTo, o runner já chama AskAsync do step de destino na mesma mensagem — o usuário recebe a próxima pergunta imediatamente, sem precisar enviar outra mensagem.

Regras desta Task

REGRA 01
Nenhuma referência ao SDK neste projeto
O projeto BotForge.Telegram.Core só referencia BotForge.Telegram.Abstractions e Microsoft.Extensions.Logging.Abstractions. Se aparecer using Telegram.Bot, é erro de camada.
REGRA 02
BotPipeline e CommandRouter e StepRunner são internal
Somente IBotPipeline é public. O consumidor não acessa as implementações concretas do Core diretamente.
REGRA 03
Descomentar o registro de IBotPipeline no DI
Após criar BotPipeline, remover o comentário em BotForgeServiceCollectionExtensions e adicionar os registros de CommandRouter e StepRunner.
