BotFoundry.Telegram.Core

The core of the hexagon — orchestrates messages, command routing, multi-step flow execution and LLM fallback. Depends only on Abstractions; never references the SDK or infrastructure.

Project Structure

src/BotFoundry.Telegram.Core/zero SDK dependency 
BotFoundry.Telegram.Core/
├── IBotPipeline.cs          ← driving port — pipeline contract
├── BotPipeline.cs           ← main orchestrator
├── CommandRouter.cs         ← selects the right ITopicHandler
└── StepRunner.cs            ← runs multi-step flows

Pipeline Decision Flow

1
Auth (optional)
Se IAuthMiddleware is registered in DI, calls IsAllowedAsync. If it returns false, the pipeline stops without invoking handlers.
2
Active step? → StepRunner
If session.HasActiveFlow, it delegates to StepRunner. The runner runs ValidateAsync → ProcessAsync and updates the session with the next step or clears the flow.
3
Command? → CommandRouter
If the message starts with /, the CommandRouter identifies the handler registered by Command and invokes HandleAsync. A return of FlowResult.Continue stores the flow in the session.
4
Free text → ILlmBridge (optional)
Se ILlmBridge is registered, forwards the message and sends the reply to the user. If it is not registered, it silently ignores the message.
5
Saves session
At the end of any branch, the pipeline calls ISessionStore.SaveAsync to persist the updated session state, unless access was denied.

IBotPipeline.cs
Driving Port
Pipeline contract — the interface that TelegramPollingAdapter uses to trigger the core. It lives in the Core because it is the contract of the hexagon's driving side, used by the adapter. 
namespace BotFoundry.Telegram.Core;

public interface IBotPipeline
{
    Task ProcessAsync(
        BotContext context,
        CancellationToken ct = default);
}
Concept — Driving Port in the Core
IBotPipeline lives in the Core (not in Abstractions) because it is an internal contract of the library — only the infrastructure adapter needs it. The consumer never invokes the pipeline directly.
BotPipeline.cs
Orquestrador
Central implementation of the pipeline. Receives the BotContext, runs the 5 steps of the decision flow and guarantees the session is saved at the end — even on an unhandled exception — unless access was denied. 
namespace BotFoundry.Telegram.Core;

internal sealed class BotPipeline : IBotPipeline
{
    private readonly ISessionStore               _sessionStore;
    private readonly CommandRouter                _router;
    private readonly StepRunner                   _stepRunner;
    private readonly IAuthMiddleware?              _auth;
    private readonly ILlmBridge?                  _llm;
    private readonly ILogger<BotPipeline>          _logger;

    // Injected via DI — IAuthMiddleware and ILlmBridge are optional
    public BotPipeline(
        ISessionStore      sessionStore,
        CommandRouter      router,
        StepRunner         stepRunner,
        ILogger<BotPipeline> logger,
        IAuthMiddleware?   auth  = null,
        ILlmBridge?        llm   = null)
    {
        _sessionStore = sessionStore;
        _router       = router;
        _stepRunner   = stepRunner;
        _logger       = logger;
        _auth         = auth;
        _llm          = llm;
    }

    public async Task ProcessAsync(
        BotContext context, CancellationToken ct = default)
    {
        try
        {
            // 1. Auth
            if (_auth is not null)
            {
                var allowed = await _auth.IsAllowedAsync(context, ct);
                if (!allowed) return;
            }

            // 2. Active step
            if (context.Session.HasActiveFlow)
            {
                await _stepRunner.ResumeAsync(context, ct);
                return;
            }

            // 3. Comando
            if (context.Text.StartsWith('/'))
            {
                await _router.RouteAsync(context, ct);
                return;
            }

            // 4. Free text → LLM
            if (_llm is not null)
            {
                var reply = await _llm.ProcessAsync(context.Text, context, ct);
                await context.SendAsync(reply, ct);
            }
        }
        finally
        {
            // 5. Persist the session unless access was denied
            await _sessionStore.SaveAsync(context.Session, ct);
        }
    }
}
Concept — finally guarantees consistency
The finally block guarantees the session is always saved — even if the handler throws an unhandled exception. This avoids sessions stuck in a corrupted state between messages. Chats denied by the auth middleware are the exception: they get no stored session.
CommandRouter.cs
Router
Receives the collection of ITopicHandler registered by the consumer and builds a lookup dictionary by Command. At runtime, it finds the handler in O(1) and invokes HandleAsync. 
namespace BotFoundry.Telegram.Core;

internal sealed class CommandRouter
{
    private readonly IReadOnlyDictionary<string, ITopicHandler> _handlers;
    private readonly ILogger<CommandRouter>                  _logger;

    public CommandRouter(
        IEnumerable<ITopicHandler> handlers,
        ILogger<CommandRouter>     logger)
    {
        _logger   = logger;
        _handlers = handlers.ToDictionary(h => h.Command, StringComparer.OrdinalIgnoreCase);
    }

    public async Task RouteAsync(
        BotContext context, CancellationToken ct)
    {
        // Extract the command — e.g. "/start args" → "start"
        var command = context.Text[1..].Split(' ')[0].ToLowerInvariant();

        if (!_handlers.TryGetValue(command, out var handler))
        {
            _logger.LogWarning("Command not registered: {Command}", command);
            return;
        }

        var result = await handler.HandleAsync(context, ct);

        // If the handler started a flow, store the active topic in the session
        if (!result.IsComplete)
            context.Session.ActiveTopic = command;
    }
}
Concept — O(1) lookup
The dictionary is built once in the constructor (startup). At runtime, each message performs only one TryGetValue — regardless of the number of registered handlers.
StepRunner.cs
StepRunner
Runs an ongoing multi-step flow. Finds the active step by ActiveStepId, validates the user's reply and processes the result — advancing, redirecting or ending the flow. 
namespace BotFoundry.Telegram.Core;

internal sealed class StepRunner
{
    private readonly IReadOnlyDictionary<string, IConversationStep> _steps;
    private readonly ILogger<StepRunner>                          _logger;

    public StepRunner(
        IEnumerable<IConversationStep> steps,
        ILogger<StepRunner>             logger)
    {
        _logger = logger;
        _steps  = steps.ToDictionary(s => s.StepId, StringComparer.OrdinalIgnoreCase);
    }

    public async Task ResumeAsync(
        BotContext context, CancellationToken ct)
    {
        var stepId = context.Session.ActiveStepId;

        if (stepId is null || !_steps.TryGetValue(stepId, out var step))
        {
            _logger.LogWarning("Step not found: {StepId}. Clearing conversation flow.", stepId);
            context.Session.ClearFlow();
            return;
        }

        // Validate — if invalid, repeat the question
        var valid = await step.ValidateAsync(context, ct);
        if (!valid)
        {
            await step.AskAsync(context, ct);
            return;
        }

        var result = await step.ProcessAsync(context, ct);

        switch (result.Kind)
        {
            case StepResultKind.Complete:
                context.Session.ClearFlow();
                break;

            case StepResultKind.JumpTo:
                context.Session.ActiveStepId = result.TargetId;
                if (_steps.TryGetValue(result.TargetId!, out var next))
                    await next.AskAsync(context, ct);
                break;

            case StepResultKind.Continue:
            default:
                // The step must already have updated ActiveStepId in ProcessAsync
                break;
        }
    }
}
Concept — Step responsibility on Continue
On StepResultKind.Continue, it is the responsibility of the ProcessAsync of the step to update context.Session.ActiveStepId to the next step. The runner assumes no implicit sequence — branching is controlled by the consumer.
Concept — AskAsync on JumpTo
When the result is JumpTo, the runner already calls AskAsync of the destination step in the same message — the user receives the next question immediately, without having to send another message.

Rules of this Task

RULE 01
No SDK reference in this project
The BotFoundry.Telegram.Core project only references BotFoundry.Telegram.Abstractions and Microsoft.Extensions.Logging.Abstractions. If using Telegram.Bot appears, it is a layering error.
RULE 02
BotPipeline, CommandRouter and StepRunner are internal
Only IBotPipeline is public. The consumer does not access the Core's concrete implementations directly.
RULE 03
Uncomment the registration of IBotPipeline in DI
After creating BotPipeline, remove the comment on BotFoundryServiceCollectionExtensions and add the registrations of CommandRouter and StepRunner.
