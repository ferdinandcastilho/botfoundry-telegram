Código C#

Ports/ISessionStore.cs
Driven Port
Define onde e como a sessão de cada usuário é persistida entre mensagens. A lib registra InMemorySessionStore automaticamente se nenhuma implementação for registrada antes (ADR-002).
namespace BotFoundry.Telegram.Abstractions.Ports;

public interface ISessionStore
{
    Task<UserSession?> GetAsync(
        long chatId,
        CancellationToken ct = default);

    Task SaveAsync(
        UserSession session,
        CancellationToken ct = default);

    Task DeleteAsync(
        long chatId,
        CancellationToken ct = default);
}
Conceito — ADR-002
O núcleo chama ISessionStore sem saber se a sessão está em memória, Redis ou banco. Trocar a implementação é questão de registro no DI — zero mudança no Core.
Ports/IMessageSender.cs
Driven Port
Abstrai o envio de respostas ao usuário. É o único ponto de contato do núcleo com o mundo externo de saída — o SDK Telegram.Bot nunca aparece no Core.
namespace BotFoundry.Telegram.Abstractions.Ports;

public interface IMessageSender
{
    Task SendTextAsync(
        long chatId,
        string text,
        CancellationToken ct = default);

    Task SendTextAsync(
        long chatId,
        string text,
        IReadOnlyList<string>? quickReplies,
        CancellationToken ct = default);
}
Conceito — ADR-003
Apenas TelegramMessageSender (projeto de adapters) implementa esta interface usando o SDK. Em testes, um FakeMessageSender coleta as mensagens em memória — sem rede, sem token.
Ports/ITopicHandler.cs
Port de Domínio
Contrato que o consumidor implementa para responder a um comando específico (/start, /ajuda…). A lib invoca este contrato quando o Routing identifica o comando.
namespace BotFoundry.Telegram.Abstractions.Ports;

public interface ITopicHandler
{
    /// Comando que este handler atende (sem "/"), ex: "start"
    string Command { get; }

    Task<FlowResult> HandleAsync(
        BotContext context,
        CancellationToken ct = default);
}
Conceito — Zona 2 (Domínio)
A lib nunca conhece a lógica de negócio do bot — ela só conhece o contrato. O consumidor registra N handlers via DI; o Routing descobre qual invocar em runtime pelo valor de Command.
Ports/IConversationStep.cs
Port de Domínio
Define uma etapa de fluxo multi-step — o que perguntar, como validar e como processar a resposta do usuário.
namespace BotFoundry.Telegram.Abstractions.Ports;

public interface IConversationStep
{
    /// Identificador único do step dentro do fluxo
    string StepId { get; }

    /// Envia a pergunta ao usuário
    Task AskAsync(
        BotContext context,
        CancellationToken ct = default);

    /// Valida a resposta recebida — retorna false para repetir a pergunta
    Task<bool> ValidateAsync(
        BotContext context,
        CancellationToken ct = default);

    /// Processa a resposta válida e decide o próximo passo
    Task<StepResult> ProcessAsync(
        BotContext context,
        CancellationToken ct = default);
}
Conceito — StepRunner (Fluxo 2)
O StepRunner do Core chama ValidateAsync → ProcessAsync a cada mensagem. StepResult retorna Continue, Complete ou JumpTo — o consumidor controla o fluxo; o núcleo executa a mecânica.
Ports/IAuthMiddleware.cs
Port Opcional
Decide se um usuário tem permissão para continuar no pipeline. Se não registrado no DI, o pipeline pula a verificação e todos os usuários passam.
namespace BotFoundry.Telegram.Abstractions.Ports;

public interface IAuthMiddleware
{
    Task<bool> IsAllowedAsync(
        BotContext context,
        CancellationToken ct = default);
}
Conceito — Gancho Opcional
A lib não impõe regras de acesso — expõe o gancho. O consumidor decide se implementa (lista de admins, token JWT, etc.). Se não registrar, o pipeline segue sem verificação.
Ports/ILlmBridge.cs
Port de Extensão
Repassa mensagens de texto livre (sem comando ativo) a um agente de linguagem externo. Ativado apenas no Fluxo 3 — quando não há comando e não há step ativo.
namespace BotFoundry.Telegram.Abstractions.Ports;

public interface ILlmBridge
{
    Task<string> ProcessAsync(
        string userMessage,
        BotContext context,
        CancellationToken ct = default);
}
Conceito — Extensão (Fluxo 3)
A integração real com OpenAI, Gemini ou outro LLM é 100% responsabilidade do consumidor. A lib só verifica se o port foi registrado e, se sim, delega a mensagem.
Models/BotContext.cs
Modelo de Fronteira
Objeto criado pelo TelegramPollingAdapter a partir do objeto do SDK e injetado no pipeline. Não contém nenhum tipo do Telegram.Bot — é a "tradução" do mundo externo para o vocabulário interno da lib.
namespace BotFoundry.Telegram.Abstractions.Models;

public sealed class BotContext
{
    public required long           ChatId   { get; init; }
    public required string         Text     { get; init; }
    public required UserSession    Session  { get; init; }
    public required IMessageSender Sender   { get; init; }

    /// Atalho para o consumidor enviar respostas sem acessar Sender diretamente
    public Task SendAsync(
        string text,
        CancellationToken ct = default)
        => Sender.SendTextAsync(ChatId, text, ct);

    public Task SendAsync(
        string text,
        IReadOnlyList<string> quickReplies,
        CancellationToken ct = default)
        => Sender.SendTextAsync(ChatId, text, quickReplies, ct);
}
Conceito — Modelo de Fronteira
BotContext é o contrato de entrada de todos os Ports de domínio. O consumidor recebe um BotContext nos seus handlers — nunca objetos do SDK. Isso garante que o código do bot seja testável sem Telegram.
Models/UserSession.cs
Modelo de Estado
Estado do usuário persistido entre mensagens — qual fluxo está ativo, em qual step está e dados coletados ao longo da conversa.
namespace BotFoundry.Telegram.Abstractions.Models;

public sealed class UserSession
{
    public required long ChatId { get; init; }

    /// Comando do fluxo ativo, ex: "cadastro". Null se nenhum fluxo ativo.
    public string? ActiveTopic  { get; set; }

    /// StepId do step atual dentro do fluxo ativo.
    public string? ActiveStepId { get; set; }

    public DateTimeOffset ExpiresAt { get; set; }

    /// Dados coletados durante a conversa (chave livre por step)
    public Dictionary<string, string> Data { get; }
        = new();

    public bool IsExpired
        => DateTimeOffset.UtcNow > ExpiresAt;

    public bool HasActiveFlow
        => ActiveTopic is not null;

    public void ClearFlow()
    {
        ActiveTopic  = null;
        ActiveStepId = null;
        Data.Clear();
    }
}
Models/FlowResult.cs
Modelo de Resultado
Retorno do ITopicHandler.HandleAsync — indica ao pipeline se o fluxo deve continuar aguardando input ou se encerrou na mesma mensagem.
namespace BotFoundry.Telegram.Abstractions.Models;

public sealed class FlowResult
{
    public bool IsComplete { get; private set; }

    /// Fluxo iniciado — aguarda próxima mensagem do usuário
    public static FlowResult Continue()
        => new() { IsComplete = false };

    /// Fluxo encerrado na mesma mensagem — sem step ativo
    public static FlowResult Complete()
        => new() { IsComplete = true };
}
Conceito — Static Factory Methods
O padrão FlowResult.Continue() e FlowResult.Complete() torna o código do consumidor expressivo e auto-documentado — é imediatamente legível o que o handler está sinalizando ao pipeline.
Models/StepResult.cs
Modelo de Resultado
Retorno de IConversationStep.ProcessAsync — instrui o StepRunner sobre o que fazer após processar o input do usuário.
namespace BotFoundry.Telegram.Abstractions.Models;

public sealed class StepResult
{
    public StepResultKind Kind     { get; private set; }
    public string?        TargetId { get; private set; }

    /// Avança para o próximo step em sequência
    public static StepResult Continue()
        => new() { Kind = StepResultKind.Continue };

    /// Encerra o fluxo — limpa o estado da sessão
    public static StepResult Complete()
        => new() { Kind = StepResultKind.Complete };

    /// Redireciona para um step específico pelo StepId
    public static StepResult JumpTo(string stepId)
        => new() { Kind = StepResultKind.JumpTo, TargetId = stepId };
}

public enum StepResultKind
{
    Continue,
    Complete,
    JumpTo
}
Conceito — JumpTo e bifurcação condicional
JumpTo é o mecanismo de bifurcação do fluxo multi-step. O consumidor pode redirecionar para qualquer step pelo StepId — o StepRunner não precisa conhecer a lógica da bifurcação, só executa o destino.

Como os Modelos se Relacionam

BotContext → IMessageSender
BotContext expõe SendAsync como atalho, delegando para IMessageSender. O consumidor nunca precisa injetar IMessageSender diretamente no seu handler.
BotContext → UserSession
A sessão está sempre disponível em context.Session. O step pode gravar dados em Session.Data["nome"] = value e lê-los nos steps seguintes.
ITopicHandler → FlowResult
O handler retorna FlowResult.Continue() se iniciou um fluxo multi-step ou FlowResult.Complete() se respondeu e encerrou tudo na mesma mensagem.
IConversationStep → StepResult
Cada step retorna Continue, Complete ou JumpTo(stepId). O StepRunner usa esses valores para avançar, encerrar ou redirecionar o fluxo.
