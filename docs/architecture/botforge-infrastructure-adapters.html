Código C#

Adapters/InMemorySessionStore.cs
Driven Adapter
Implementação padrão de ISessionStore usando ConcurrentDictionary para acesso concorrente sem locks explícitos. Registrada automaticamente se o consumidor não registrar outra implementação (ADR-002).
namespace BotForge.Telegram.Adapters;

internal sealed class InMemorySessionStore : ISessionStore
{
    private readonly Dictionary<long, UserSession> _store = new();
        public async Task<UserSession?> GetAsync(
        long chatId, CancellationToken ct = default)
    {
        _store.TryGetValue(chatId, out var session);
        return session
    }

    public async Task SaveAsync(
        UserSession session, CancellationToken ct = default)
    {
        _store[session.ChatId] = session
    }

    public async Task DeleteAsync(
        long chatId, CancellationToken ct = default)
    {
        _store.TryRemove(chatId, out _)
    }
}
Conceito — internal + Driven Adapter (ADR-002)
internal garante que o consumidor não acessa este tipo diretamente — só via ISessionStore. O ConcurrentDictionary garante thread-safety para múltiplas mensagens simultâneas de um mesmo bot sem gerenciamento manual de locks.
Adapters/TelegramMessageSender.cs
Driven Adapter — SDK
Único arquivo da lib que usa Telegram.Bot. Implementa IMessageSender delegando ao ITelegramBotClient do SDK. Todo o resto da lib usa apenas a interface.
using Telegram.Bot;
using Telegram.Bot.Types.ReplyMarkups;

namespace BotForge.Telegram.Adapters;

internal sealed class TelegramMessageSender : IMessageSender
{
    private readonly ITelegramBotClient _client;

    public TelegramMessageSender(ITelegramBotClient client)
        => _client = client;

    public Task SendTextAsync(
        long chatId,
        string text,
        CancellationToken ct = default)
        => _client.SendMessage(chatId, text, cancellationToken: ct);

    public Task SendTextAsync(
        long chatId,
        string text,
        IReadOnlyList<string>? quickReplies,
        CancellationToken ct = default)
    {
        if (quickReplies is null or { Count: 0 })
            return SendTextAsync(chatId, text, ct);

        var markup = new ReplyKeyboardMarkup(
            quickReplies.Select(r => new KeyboardButton(r)))
        { ResizeKeyboard = true, OneTimeKeyboard = true };

        return _client.SendMessage(chatId, text,
            replyMarkup: markup, cancellationToken: ct);
    }
}
Conceito — ADR-003 (isolamento do SDK)
O único using Telegram.Bot de toda a lib está aqui. Se o SDK sofrer breaking change, a correção fica contida neste único arquivo — o Core e o consumidor não são afetados.
Adapters/TelegramPollingAdapter.cs
Driving Adapter
Hosted service que mantém o loop de long polling com o Telegram. Recebe updates do SDK, traduz para BotContext e aciona o pipeline do Core. É o único ponto de entrada de mensagens na lib.
using Telegram.Bot;
using Telegram.Bot.Polling;
using Telegram.Bot.Types;
using Telegram.Bot.Types.Enums;

namespace BotForge.Telegram.Adapters;

internal sealed class TelegramPollingAdapter : IHostedService
{
    private readonly ITelegramBotClient _client;
    private readonly IBotPipeline        _pipeline;
    private readonly IMessageSender      _sender;
    private readonly ISessionStore       _sessionStore;
    private readonly ILogger<TelegramPollingAdapter> _logger;

    // ... construtor via DI ...

    public Task StartAsync(CancellationToken ct)
    {
        var options = new ReceiverOptions
        {
            AllowedUpdates = [UpdateType.Message]
        };

        _client.StartReceiving(
            updateHandler:      HandleUpdateAsync,
            pollingErrorHandler:HandleErrorAsync,
            receiverOptions:    options,
            cancellationToken:  ct);

        return Task.CompletedTask;
    }

    public Task StopAsync(CancellationToken ct)
        => Task.CompletedTask;

    private async Task HandleUpdateAsync(
        ITelegramBotClient _,
        Update update,
        CancellationToken ct)
    {
        // Filtra: apenas mensagens de texto
        if (update.Message?.Text is not { } text) return;

        var chatId  = update.Message.Chat.Id;
        var session = await _sessionStore.GetAsync(chatId, ct)
                      ?? new UserSession { ChatId = chatId,
                             ExpiresAt = DateTimeOffset.UtcNow.AddHours(24) };

        // Tradução: Update (SDK) → BotContext (lib)
        var context = new BotContext
        {
            ChatId  = chatId,
            Text    = text,
            Session = session,
            Sender  = _sender
        };

        await _pipeline.ProcessAsync(context, ct);
    }

    private Task HandleErrorAsync(
        ITelegramBotClient _,
        Exception ex,
        CancellationToken ct)
    {
        _logger.LogError(ex, "Polling error");
        return Task.CompletedTask;
    }
}
Conceito — Driving Adapter + Modelo de Fronteira
Este adapter faz a tradução Update (SDK) → BotContext (lib). Depois disso, o objeto Update nunca mais aparece — o Core só enxerga BotContext. É aqui que o mundo externo "entra" no hexágono.
DependencyInjection/BotForgeServiceCollectionExtensions.cs
Entry Point Público
Único tipo public deste projeto. Registra todos os serviços internos da lib no DI do .NET. O consumidor chama apenas AddBotForge() no Program.cs — sem conhecer nenhum tipo interno.
namespace BotForge.Telegram.DependencyInjection;

public static class BotForgeServiceCollectionExtensions
{
    public static IServiceCollection AddBotForge(
        this IServiceCollection services,
        Action<BotForgeOptions> configure)
    {
        var options = new BotForgeOptions();
        configure(options);

        // SDK
        services.AddSingleton<ITelegramBotClient>(
            new TelegramBotClient(options.Token));

        // Driven adapters de infraestrutura
        services.AddSingleton<IMessageSender, TelegramMessageSender>();

        // ISessionStore: só registra fallback se consumidor não registrou antes
        if (!services.Any(d => d.ServiceType == typeof(ISessionStore)))
            services.AddSingleton<ISessionStore, InMemorySessionStore>();

        // Core (pipeline — a implementar na próxima task)
        services.AddSingleton<IBotPipeline, BotPipeline>();

        // Driving adapter — mantém o loop de polling
        services.AddHostedService<TelegramPollingAdapter>();

        return services;
    }
}

public sealed class BotForgeOptions
{
    public required string Token { get; set; }
    public TimeSpan SessionExpiry { get; set; } = TimeSpan.FromHours(24);
}
Conceito — Convenção DI (ADR-002)
A verificação services.Any(d => d.ServiceType == typeof(ISessionStore)) é o mecanismo de fallback — o consumidor registra seu store antes de chamar AddBotForge() e a lib respeita a escolha.
Atenção — dependência futura
BotPipeline e IBotPipeline ainda não existem — serão criados na próxima task (Core). Por ora, deixe o registro comentado ou use um placeholder para que o build passe.

Regras desta Task

REGRA 01
Todos os adapters são internal
Apenas BotForgeServiceCollectionExtensions e BotForgeOptions são public. O consumidor nunca instancia um adapter diretamente — só via DI.
REGRA 02
using Telegram.Bot só em dois arquivos
TelegramMessageSender.cs e TelegramPollingAdapter.cs são os únicos que podem importar o SDK. Nenhum outro arquivo do projeto deve referenciar tipos do Telegram.Bot.
REGRA 03
Registro de IBotPipeline fica comentado
BotPipeline ainda não existe. Deixe a linha de registro comentada no DI para que o dotnet build passe sem erros. Será descomentada na task do Core.
